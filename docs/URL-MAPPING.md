# Legacy URL mapping (WordPress → Hugo)

How every URL from the old WordPress site maps onto the Hugo site, and how to
keep the old URLs working. Regenerate with `python scripts/url_analysis.py`
(after `hugo`); `--caddy` emits the redirect block below.

## Summary

Of the **448** page URLs in the wget archive (the live WordPress site):

| Class | Count | % | Meaning |
|---|---:|---:|---|
| **Direct** | **423** | 94% | Hugo serves a real page at the *identical* URL — nothing to do |
| **Alias** | **23** | 5% | Old URL differs from the Hugo canonical — needs a redirect |
| **Missing** | **2** | 0.4% | `/author/editor/page/{2,3}/` pagination; all those posts are on `/author/editor/` |

**The 23 that change are all non-canonical duplicates.** The canonical form of
each (the URL most likely cited externally) is already in the Direct 94% and is
served unchanged. There are also **6 brand-new** URLs that never existed in
WordPress: `/search/`, the `/author/`, `/category/`, `/featured/`, and `/3-2/`
index pages, and one article's pretty URL (`/1-2/going-beyond-…-antley/`, whose
old `.html` form is redirected).

### Why the 23 changed
- **15 — flat issue-root duplicate → sectioned canonical.** WordPress served the
  same post at both `/<issue>/<slug>/` and `/<issue>/<section>/<slug>/`; the
  page's `rel="canonical"` pointed at the sectioned form, so the flat form
  redirects. e.g. `/1-1/theory-first-by-ben-schmidt/` →
  `/1-1/conversations/theory-first-by-ben-schmidt/`.
- **8 — "ugly" `.html` permalink → pretty directory URL.** e.g.
  `/2-3/big-smart-clean-messy-data-in-the-humanities.html` →
  `/2-3/big-smart-clean-messy-data-in-the-humanities/`.

## How the old URLs are kept working

Two equivalent strategies; the site currently uses the first.

| | **Hugo aliases** (current) | **Caddy 301 redirects** |
|---|---|---|
| Mechanism | HTML meta-refresh stub, HTTP **200** | true **301 permanent** |
| SEO / link equity | weaker (Google still follows) | strongest signal |
| Latency | extra HTML round-trip | instant |
| Lives in | `content/` front-matter `aliases` (host-portable) | the Caddyfile (in `Dockerfile`, version-controlled) |
| Maintenance | zero (site is frozen) | zero (site is frozen) |
| Status | **already generated** by the converter | opt-in (paste the block below) |

**Recommendation:** for a citation-bearing archive, true **301s are the cleaner
choice** and cost only 25 stable lines — so prefer Caddy 301s, and set
`disableAliases = true` in `hugo.toml` to stop emitting the redundant stubs.
Hugo aliases are nonetheless perfectly acceptable (the affected URLs are
non-canonical duplicates and the site never changes), and need no infra.

> Either way, do **not** add both for the same path — Caddy's `redir` runs before
> `file_server`, so the alias stub would simply be shadowed (harmless but dead).

## Media URLs

Image/upload and download URLs (`/wp-content/uploads/…`, `/files/…`) are **not**
hosted by this site — they are referenced absolutely at
`https://journalofdigitalhumanities.org/…`. That origin must keep serving those
two paths (directly or via the same redirect) for figures and downloads to load.
